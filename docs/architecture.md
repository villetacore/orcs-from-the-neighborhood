# Архитектура

## Поток данных

`tools/build_deck.py` + `tools/content.py` → `data/cards.json` → `orcs-core::CardDb` → `Game` → команды клиента → автосохранение. Данные карт встраиваются при компиляции. `tools/build_cards.py` строит печатные SVG и HTML из того же JSON. Числовые правила не дублируются в картинках.

## Движок правил

`crates/orcs-core` зависит только от serde, serde_json и thiserror.

| Модуль | Назначение |
|---|---|
| `cards` | Каталог, категории, эффекты, семейства, цены, награды, ступени, реплики |
| `state` | Игрок, фаза, бонус, отложенное решение и его владелец |
| `game` | Создание партии, Барахло, добор, хроника, приватный владелец, учёт карт |
| `economy` | Разборки, витрина, покупки и бартер, подработка, районы, перки, денежная помощь, финальный вызов |
| `play` | Допустимость и розыгрыш карты; одна проверка для кнопки и drag-and-drop |
| `combat` | Состав силы, круг вмешательства, помощь, последнее слово, награда и штраф |
| `effects` | Исследование, события, добровольный сброс и защищённая потеря |
| `choices` | Согласие, скрытый просмотр, выбор перка и другие обязательные решения |
| `turn` | Подготовка, замена, обмен, лимит руки и переход хода |
| `rng`, `save` | Сериализуемый PCG32 и формат сохранения 4 |

`Game::deck/discard` — Барахло; `trouble_deck/trouble_discard` — Разборки. Верх обеих колод — конец вектора. `market` содержит до трёх физических карт Барахла. Все сбросы производственного кода маршрутизируются через `discard_card`. Физические 56 карт находятся ровно в одном месте: колоды, сбросы, руки, слоты, витрина, бой или выбор из колоды. Ссылки `last_card`, временные бонусы и варианты согласия не владеют картами.

Финальный враг — публичный компонент каталога, не физическая карта основной колоды. Районы лежат в своей стопке с текущей открытой картой. Перки выбираются из открытого каталога; взятый перк недоступен другим. При учёте карт отдельно проверяются эксклюзивность перков и наличие всех районов.

`Player::unlocked_tiers` фиксирует право выбора один раз; `perks` хранит карты, `active_perks` фильтрует их по текущему уровню. `final_ready` обновляется только в начале собственного хода и не даёт вызвать финал немедленно после роста до 9.

Деньги — открытый беззнаковый кошелёк. Покупка сначала проверяет фазу, лимит, витрину, платёжную карту и баланс; при отказе состояние остаётся прежним. Номиналы физических монет не влияют на кошелёк. Банк не имеет лимита. Скидки ограничены минимумом 1, возврат не снижает чистую цену ниже 1.

Все решения хранятся в `Game::choices`. Скрытую информацию видит `owner()` первого решения, иначе текущий участник боя или активный игрок. Разведка не записывает содержимое карты в общую хронику. Денежная помощь списывает монеты только после согласия получателя; договор переживает сохранение.

## Клиент

`crates/orcs-game`: Bevy + bevy_egui. `session::GameCommand` передаёт действия в движок; `apply_commands` применяет их и сохраняет успешный результат. Интерфейс не меняет `Game` напрямую.

`ui::model` отвечает за доступность действий, приватную ширму и описание боя; `ui::table` — стол, кошельки, перки, витрину и район. Магазин скрывается при обязательном выборе. `ui::card` накладывает текст, цену и статистику на изображение, `gallery` показывает весь каталог, `rules` встраивает `rules/quickstart.md`.

`assets` загружает PNG и держит текстуры; несколько перков могут ссылаться на один явно указанный рисунок. `capture` делает снимки окна после загрузки всех изображений. `persistence` находит корень и папку данных приложения, пишет JSON атомарно.

## Контент и ассеты

`tools/build_deck.py` содержит базовые карты и сборку; `tools/content.py` — актуальные тексты, изменения образов и новые компоненты. `prompts/manifest.json` соответствует всему каталогу; `prompts/generated.json` хранит точные промпты новых изображений. `art_reuse` в данных указывает намеренное повторное использование рисунка перком.

`tools/build_cards.py` строит 90 SVG 63 × 88 мм и печатный HTML с различимыми рубашками. Он проверяет вместимость текстовых блоков. `tools/validate_assets.py` проверяет состав, цены, типы, пути, PNG, повторное использование и SVG. `tools/build_coins.py` создаёт OpenSCAD и STL номиналов 1/5/10 и проверяет замкнутость сетки. Последствие поражения врага не пишется в `text`: экран (`CardDef::rules_text`) и SVG добавляют его из поля `penalty` одинаково. `tools/build_audit.py` строит `output/content-audit.md` из решений `tools/audit/decisions.py`.

После правок контента: сборка JSON → печатные карты → проверка ассетов → тесты → пересборка приложения. Изменение схемы состояния требует решения о формате сохранений; несовместимые старые партии отклоняются явно. Генерация новых изображений не запускается при обычной сборке.

## Расширение

Новая карта со старым эффектом: определение в генераторе, иллюстрация, пересборка и проверка. Новый эффект: перечисление в `cards`, проверка допустимости, обработчик и сценарный тест. Новый выбор: `ChoiceKind`, ветка `choose`, подпись и проверка владельца. Сеть или бот должны работать через публичные действия `Game`, а не менять состояние напрямую.

Старые исходники в `legacy/godot` справочные. Актуальные правила только в [quickstart.md](../rules/quickstart.md), творческое направление — в [game.md](game.md), фактические проверки — в [validation.md](validation.md).
