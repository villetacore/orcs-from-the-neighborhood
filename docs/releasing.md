# Выпуск версий

## CI

`CI` запускается для pull request и изменений `main`: проверяет публичные файлы,
пересобирает каталог, печатные карты, аудит и монеты, запрещает устаревшие результаты.
На Linux, Windows и macOS запускаются форматирование, Clippy, тесты, сборка
и проверка командной строки без GPU.

Rust закреплён в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.
Задания имеют доступ только на чтение; запись в репозиторий разрешена лишь
заданию публикации релиза. Дополнительные секреты для публикации не нужны.

## Релиз

1. Обновите `workspace.package.version` в `Cargo.toml` и `Cargo.lock`
   (`cargo check --workspace`), добавьте запись в `CHANGELOG.md`.
2. Дождитесь зелёного CI на `main`. Проверьте интерфейс и партию вручную.
3. Создайте тег, точно совпадающий с версией Cargo:

   ```sh
   git tag v0.4.0
   git push origin v0.4.0
   ```

`Release` повторяет обязательные проверки, собирает Linux x64, Windows x64,
macOS Apple Silicon и Intel. Каждая сборка содержит нужные PNG, правила,
лицензию и инструкцию; macOS получает `.app`. Проверка распаковывает архив
во временную папку вне дерева исходников и запускает `--version` и `--check-assets`.
Пути машины сборки заменяются в диагностических данных компилятора.

После успешной сборки всех четырёх вариантов публикуется GitHub Release с ZIP
и `SHA256SUMS`. До загрузки файлов релиз остаётся черновиком. Для повторного
запуска после ошибки публикации используйте существующий черновик: workflow
умеет продолжать загрузку. Опубликованные версии не перезаписывайте;
для исправлений выпускайте новый patch-тег.

Ручной запуск `Release` на ветке собирает архивы в Actions artifacts,
но не создаёт опубликованный релиз. Поддерживаемые runner-образы перечислены
в [документации GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

## Локальная упаковка

После `cargo build --release --locked`:

```sh
python3 tools/package_release.py --platform macos-aarch64 --binary target/release/orcs-from-the-neighborhood
```

Также доступны `macos-x86_64`, `linux-x86_64`, `windows-x86_64` (для Windows
передайте путь к `.exe`). Упаковщик не выполняет кросс-компиляцию.
Архивы и индивидуальные `.sha256` появятся в игнорируемой папке `dist/`.
Упаковка использует явный список ресурсов и не переносит IDE, локальные настройки,
исходные журналы генератора и сохранения игроков.

## Перед публикацией

- Проверьте `python3 tools/check_repository.py`, статус Git и имя/email автора коммита.
- Не добавляйте личные пути или email в сообщения коммитов и логи.
- Для защиты `main` включите в GitHub ruleset обязательные проверки
  `Content and privacy` и `Rust (...)`, запретите force push.
- Подпись Windows и Apple Developer ID / нотариализация требуют отдельных
  сертификатов и учётных записей; текущий pipeline их не использует.
